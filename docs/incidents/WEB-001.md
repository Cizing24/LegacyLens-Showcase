# WEB-001 — Page Lifecycle 覆寫尚未儲存的案件編輯

分類：**Controlled Fault Injection**。僅存在於 `.runtime/web001-*` 本機複本，並非企業事故。Issue：[WEB-001 #2](WEB-001.md)。

## Problem / Impact / Environment

修改已存在案件主旨、說明後切換分類，伺服器 Page_Load 若每次都載入 SQL 資料，會把尚未儲存的輸入覆寫為資料庫舊值。影響是草稿遺失；測試不按儲存，不破壞案件資料。環境為 .NET Framework 4.8、IIS Express、SQL Server LocalDB、Playwright Chromium。

## Reproduction

1. 先依 local development guide 建置與 Seed。
2. 執行 `tools/reproduction/prepare-web001.ps1 -Port 5190`。只對隔離複本將 `if (!IsPostBack)` 改成無條件 binding，編譯並啟動另個 IIS Express。
3. 設 `LEGACYLENS_URL=http://localhost:5190`，執行 `npx playwright test tests/E2E/web001.spec.js`。
4. 測試登入、開啟案件、輸入草稿及說明、切換分類，明確等到 CaseEdit POST=200 與伺服器提示。
5. `toHaveValue(draft)` 失敗，actual 回到資料庫原主旨；見 [red report](../testing/web001-red.json) 與 [真實失敗畫面](../media/web001-before.png)。

## Hypotheses / Investigation / Root Cause

先排除「瀏覽器根本沒送出 POST」；實際調查確實先遇到 [DEV-002 CSP 問題](DEV-002-postback-csp.md)，所以補強 HTTP response 斷言。再比較預期／實際值，確認 SQL 舊值覆蓋草稿，非 SQL Save 遺失。

Web Forms 載入 ViewState 與 posted data 後才執行 Page_Load。這時重新 DataBind／LoadCase 會覆寫 TextBox 屬性，接著才執行 SelectedIndexChanged。根據 [Microsoft Page Lifecycle](https://learn.microsoft.com/en-us/previous-versions/aspnet/ms178472(v=vs.100)) 的順序，問題發生在 binding 時機。

## Alternatives / Trade-offs / Decision

- **僅初次請求 binding**：改動小，保留 ViewState 的表單資料，避免重複 SQL 讀取。需特別處理儲存成功後的刷新。
- **在 Init 重建所有控制項，再由 post data 還原**：適合動態控制項，但需重新設計載入與選項建立順序，增加目前固定表單的維護成本。
- **Save 前從 Request.Form 取值補救**：耦合控制項名稱，無法解決畫面先遺失草稿，不採用。

選擇 `!IsPostBack`，儲存成功使用 Post/Redirect/Get；分類選項保留在 ViewState，歷程可獨立刷新。外部 JS 以原生 requestSubmit 送出分類 Postback，無需 unsafe-eval。

## Implementation / Verification

`repair-web001.ps1` 實際把正確的 guarded binding 寫回隔離原始碼並重新編譯；相同斷言由 **1 failed → 1 passed**，主旨與說明皆保留。見 [green report](../testing/web001-green.json)。最初 Copy-Item 還原保留較舊時間戳，讓 incremental MSBuild 跳過重編；改為 WriteAllText 寫入目前時間戳後才取得真正 green。這個 harness 問題沒有冒稱修復成功。

正式應用無注入開關；根目錄保留 regression，並在 Page_Load 註解 binding 原因。剩餘風險：新增動態控制項或關閉 ViewState 時，需重新檢查生命週期；其他瀏覽器尚未驗證。
